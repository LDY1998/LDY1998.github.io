在这个系列的第一篇中，我们从 RNN 出发，看到 Attention 如何让模型不再把整段输入都挤进一个固定向量；到了 Transformer，循环结构进一步从主干中消失，序列中的位置可以直接建立联系，训练也不必再沿时间一步步进行。

但在上一篇的结尾，历史似乎绕了一圈。Linear Attention 不再保存不断增长的逐 token K/V，而是把历史压缩进固定大小的矩阵状态：新 token 到来时更新状态，需要输出时再由 Query 从状态中读取。这个计算过程，又可以写成熟悉的递归形式：

$$
h_t=F(h_{t-1},x_t).
$$

如果 Attention 当初是为了摆脱 RNN 的固定状态瓶颈，那么今天的模型为什么又主动把历史压回状态？这究竟是一次架构上的倒退，还是 RNN 当年真正的问题从来都不只是“存在递归”？

答案藏在两个经常被混为一谈的概念中：**递归推理不等于顺序训练，固定大小的状态也不等于旧式 RNN 的单一隐藏向量。**现代递归模型希望保留的，是 RNN 在生成阶段只需携带有限状态的优点；它们希望避免的，则是旧式 RNN 难以并行训练、长距离信息不断经过非线性状态传递，以及所有历史被不加区分地揉进一个向量的问题。

Linear Attention 打开了这扇门：同一个序列层可以在训练时写成并行形式，在生成时写成递归形式。沿着这条路线，[RetNet](https://arxiv.org/abs/2307.08621) 为状态加入随距离衰减的 Retention，[RWKV](https://arxiv.org/abs/2305.13048) 把 Receptance、时间混合与 Key–Value 记忆组合起来；另一边，从控制理论和信号处理发展而来的 State Space Model 也开始进入语言建模，[Mamba](https://arxiv.org/abs/2312.00752) 又让状态更新随输入发生变化。到了 [Mamba-2](https://arxiv.org/abs/2405.21060)，Attention 与 State Space Model 甚至可以被放进同一套结构化矩阵框架中比较。

这些方法并不是同一个算法换了不同名字。RetNet 和 RWKV 与 Linear Attention 的递归写法联系更直接，Mamba 则来自 State Space Model 的参数化传统；它们共享的是同一个目标：**既获得 Transformer 的大规模并行训练能力，又在生成时像 RNN 一样用有限状态持续运行。**

因此，本文讨论的不是“RNN 战胜 Transformer”的新一轮架构竞赛，而是一个更具体的问题：Transformer 时代的模型怎样重新设计递归状态，使它能够被并行训练、按内容读取，并且学会选择应该写入、保留和遗忘什么？

## RNN 失败的不是“递归”本身

先回到最普通的 RNN。给定当前输入 $x_t$ 和上一时刻状态 $h_{t-1}$，模型通过一个带参数的非线性函数得到新状态：

$$
h_t=f(W_xx_t+W_hh_{t-1}+b).
$$

这个结构把历史浓缩进固定维度的 $h_t$。它的优势非常明确：无论已经处理了十个还是一万个 token，模型传给下一步的状态大小都不变。生成时，每一步所需的状态空间和更新成本不会随着上下文长度继续增长。

真正的问题来自这份状态承担任务的方式。

在早期 Encoder–Decoder 中，Decoder 往往只能通过 Encoder 的最后状态读取整段输入。长句中的实体、顺序和细节都要竞争同一个有限接口，这是 Attention 最初试图解决的固定向量瓶颈。对于普通语言模型，虽然不存在完全相同的 Encoder 最终状态接口，但每条新信息仍要反复穿过

$$
h_{t-1}\rightarrow h_t\rightarrow h_{t+1}\rightarrow\cdots
$$

这条递归链。旧信息不仅可能在一次次更新中被覆盖，它对远处输出的影响也必须经过许多次非线性变换。LSTM 和 GRU 用门控缓解了遗忘与梯度传播问题，却没有改变时间步之间的依赖：计算 $h_t$ 之前，必须先得到 $h_{t-1}$，因此训练很难在序列维度充分并行。

Attention 改变了记忆接口。它不再要求一个状态独自代表全部过去，而是保留各个位置的表示，让当前 Query 根据内容选择要读取的 Key 和 Value。Transformer 又进一步移除循环主干，使训练时所有位置的表示都能并行计算。历史不再只通过一条递归链传递，而是被展开成一份可直接寻址的 token 列表。

不过，展开历史也改变了生成阶段的状态。一个标准因果 Transformer 每生成一个 token，都会把新的 K/V 追加到 Cache 中。若把自回归生成也写成状态更新，它当然仍是一种递归过程：

$$
\mathcal{M}_t=
\mathcal{M}_{t-1}\cup\{(k_t,v_t)\}.
$$

只是这里的状态 $\mathcal{M}_t$ 不再是固定向量，而是截至当前为止的全部 K/V。模型获得了逐 token 的精确读取能力，代价是状态随上下文不断增长；每个新 Query 也要从越来越长的历史中查找信息。

从这个角度看，RNN 与 Transformer 并不是“有状态”和“无状态”的区别。二者在自回归生成时都携带历史，真正不同的是历史以什么形式存在：

| 架构 | 生成时保留的历史 | 怎样读取历史 | 训练时的序列并行 | 主要代价 |
|---|---|---|---|---|
| 传统 RNN | 固定大小的隐藏向量 | 新输入与旧状态共同更新 | 较弱 | 信息挤在单一状态中，长程传播困难 |
| 标准 Transformer | 随序列增长的逐 token K/V | Query 对历史位置进行内容寻址 | 较强 | K/V 状态与读取成本持续增长 |
| 现代递归模型 | 固定大小的向量或矩阵状态 | Query、门控或选择机制读取和更新 | 争取保留并行形式 | 有限状态中的容量、覆盖与干扰 |

第三行正是 Linear Attention、Retention、RWKV 和 State Space Model 所在的探索区域。它们不是简单地在前两种架构中选一边，而是试图组合二者的属性：用固定状态替代无限增长的历史列表，同时设计一种可以并行展开的更新规则。

### 递归推理，不一定意味着顺序训练

上一篇已经看到，因果 Linear Attention 可以维护矩阵状态：

$$
S_t=S_{t-1}+\phi(k_t)v_t^{\mathsf T}.
$$

如果进行自回归生成，这个公式自然可以从 $S_{t-1}$ 递推到 $S_t$；但在训练时，所有位置的 Key 和 Value 已经同时已知，于是每个状态也可以写成前缀和：

$$
S_t=\sum_{j\leq t}\phi(k_j)v_j^{\mathsf T}.
$$

加法满足结合律，因此这些前缀状态可以通过并行 Scan 或分块方式计算，而不必像普通非线性 RNN 那样严格逐步执行。这说明同一个模型层可以拥有两种等价视角：

- **并行形式**：训练时同时处理一段序列，发挥现代加速器擅长大规模矩阵计算的能力；
- **递归形式**：生成时只接收新 token，并更新固定大小的状态，不再携带不断增长的 K/V Cache。

现代 RNN 的“回归”，首先回归的正是这种递归推理形式，而不是传统 RNN 的完整计算方式。它把问题从“要不要保存状态”推进成“怎样设计一种既能并行计算、又能递归更新的状态”。

但最简单的线性累加只是把所有历史不断叠进 $S_t$：它不会主动遗忘，也不知道某条新信息应该覆盖、修正还是保留旧信息。固定状态一旦重新出现，RNN 时代那个更深的问题也随之回来——有限的记忆应该怎样管理？RetNet 与 RWKV 给出的第一类回答，是让不同时间距离和不同输入拥有不同的保留权重。
